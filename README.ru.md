# git-repos

[English](README.en.md) · **Русский**

CLI сверяет локальные git-репозитории с аккаунтом провайдера (сейчас — GitHub) и показывает,
что рассинхронизировано.

## Команды

| Команда | Что делает |
| --- | --- |
| `diff` | показывает расхождения |
| `status` | показывает ветку и состояние рабочего каталога локальных репозиториев |
| `update` | делает `git fetch` дефолтной ветки во всех сопоставленных репозиториях, показывая спиннер с числом репозиториев в работе |
| `sync` | создаёт недостающее с обеих сторон: приватный репозиторий на GitHub для локальных и `git clone` для удалённых |
| `clean-local` | удаляет локальные репозитории, у которых нет удалённого |
| `clean-remote` | удаляет удалённые репозитории, у которых нет локального |
| `do` | последовательно выполняет команду внутри каждого отобранного репозитория |
| `completion` | печатает скрипт автодополнения для bash или zsh |
| `install-completions` | ставит автодополнение в bash и zsh |
| `uninstall-completions` | убирает автодополнение из bash и zsh |

Таблицы печатаются в рамках и подгоняются под ширину терминала: колонки ужимаются только когда строка
не влезает, а в пайпе (stdout не терминал) значения печатаются целиком.

Без команды `git-repos` печатает список команд и завершается с кодом `2`; `git-repos -h` печатает тот же
список и общие флаги.

### diff

1. Рекурсивно ищет `.git` от текущего каталога (или от `-C <dir>`); найдя репозиторий, внутрь него не спускается.
2. Берёт список репозиториев аккаунта у провайдера. Имя из `origin` сопоставляется без учёта регистра, а если
   в списке его нет — делается точечный запрос `GET /repos/{owner}/{name}`, который следует за редиректом
   переименования. Так репозиторий, переименованный на GitHub или записанный в origin в другом регистре, не
   попадает одновременно в «только локально» и «только на удалённом».
3. Пока идёт работа, в stderr крутится спиннер: номер фазы, сама фаза, текущий объект и процент —
   `phase 1/4 · local scan · ~/tools/web · 37% (1200 of 3200 directories)`, `phase 2/4 · github api ·
   repository list, page 2 of 3 · 73% (100 of 137 repositories)`, `phase 3/4 · matching against
   github · ~/tools/foo · 40% (4 of 10)`, `phase 4/4 · checking branches · dimkarp93/git-repos · 70%
   (7 of 10) · in flight — 8`. Спиннер включается только когда stderr — терминал, и снимается флагом
   `--no-progress`.
4. Печатает две таблицы в рамках, с названиями:
   - **Repository sets** — что есть только локально и только на удалённом (совпадения не показываются);
   - **Default branch status** — кто от кого отстаёт.

Цвета статусов:

| Статус | Цвет | Что делать |
| --- | --- | --- |
| `conflict` | красный | ветки разошлись, ни один коммит не предок другого |
| `behind → pull` | оранжевый | локальный отстаёт |
| `ahead → push` | жёлтый | удалённый отстаёт |
| `synced` | серый | ничего (показывается только с `--all`) |

Если `origin` отличается от каноничного имени, печатается отдельная таблица `Origin does not match the canonical
name`, а в таблице статусов имя показывается как `owner/canonical (origin: owner/из-origin)`. Сам `origin`
при этом не меняется.

Колонка `LAST FETCH` подсвечивается: ≥ 3 дней — жёлтым, ≥ 10 — оранжевым, ≥ 30 или `never` — красным.

### status

Обходит локальные репозитории (провайдер и токен не нужны) и печатает для каждого ветку, а после неё
колонку `MARKS`. В ней перечислены **все** метки, которые сработали для репозитория — каждая своим
цветом, и каждая ровно соответствует одноимённому фильтру:

- `[feature]` пурпурным, имя ветки при этом синим — HEAD не на дефолтной ветке (дефолтная берётся из `refs/remotes/origin/HEAD`,
  иначе — локальные `main`/`master`); detached HEAD показывается как `detached` и тоже помечается;
- `[in-develop]` жёлтым — в рабочем каталоге есть незакоммиченные изменения или untracked-файлы;
- `[hotfix]` красным — изменения есть, но репозиторий на дефолтной ветке;
- `[pushable]` зелёным — фича-ветка с чистым рабочим деревом;
- `[wip]` синим — есть хоть что-то из двух: фича-ветка **или** изменения.

Метки не исключают друг друга, поэтому строка обычно выглядит как `[feature] [pushable] [wip]`.

Пока идёт обход, в stderr крутится спиннер: `phase 1/2 · local scan · /mnt/hdd/backup · 96%
(26407 of 27471 directories)`, затем `phase 2/2 · repository status · ~/tools/md-docx · 45% (15 of 33)`.
Снимается флагом `--no-progress`.

Коды возврата: `0` — успех, `2` — часть репозиториев прочитать не удалось.

### Фильтры

`diff` и `status` умеют показывать только часть результата. Имена фильтров у команд не пересекаются,
поэтому `do` принимает их все сразу.

| Фильтр | Команды | Что оставляет |
| --- | --- | --- |
| `--local` | diff, do | есть только локально |
| `--remote` | diff, do | есть только на удалённом |
| `--behind` | diff, do | локальная дефолтная ветка отстаёт |
| `--ahead` | diff, do | удалённая дефолтная ветка отстаёт |
| `--synced` | diff, do | совпадает (показывается даже без `--all`) |
| `--conflict` | diff, do | ветки разошлись |
| `--failed` | diff, do | сравнить не удалось: `error`, `unknown`, `no local branch` |
| `--feature` | status, do | HEAD не на дефолтной ветке |
| `--in-develop` | status, do | есть незакоммиченные или untracked-файлы |
| `--wip` | status, do | `[feature]` **или** `[in-develop]` |
| `--hotfix` | status, do | правки есть, но репозиторий на дефолтной ветке (ветку под них не завели) |
| `--pushable` | status, do | фича-ветка, рабочее дерево чистое |
| `--branch <подстрока>` | diff, status | ветка (в diff — дефолтная, в status — текущая) содержит подстроку без учёта регистра |
| `--project <подстрока>` | diff, status | имя репозитория (без owner) содержит подстроку без учёта регистра |

Несколько фильтров сразу работают как **ИЛИ** — объединение выборок. Таблица, для которой не включён ни один фильтр, не печатается: `diff --behind` покажет только
таблицу веток. В итоговой строке дописывается `· filter: --behind, --wip`, а счётчики считают
показанные строки. Код возврата `diff` по-прежнему считается по **полному** отчёту: это ответ на
вопрос «есть ли расхождения вообще», а не «в выборке».

`--branch` и `--project` работают иначе: это не категория статуса, а дополнительное условие
**И** поверх остальных фильтров — `diff --behind --project foo` покажет только отстающие
репозитории, чьё имя содержит `foo`. Доступны только в `diff` и `status` (в `do` их нет).

### do

```sh
git-repos do [фильтры] [-C dir] [--dry-run] -- <команда> [аргументы...]
```

Отбирает репозитории теми же фильтрами и последовательно выполняет команду внутри каждого:

- команда запускается как `sh -c` с рабочим каталогом репозитория; `stdin`, `stdout` и `stderr`
  наследуются напрямую, поэтому работают пейджер, цвет и интерактивный ввод (пароль, редактор);
- один аргумент передаётся в шелл как есть — работают пайпы, глобы и `&&`
  (`git-repos do -- 'git log --oneline -1 | cat'`); несколько аргументов экранируются по отдельности,
  поэтому `git-repos do -- git commit -m "two words"` не разваливается;
- всегда последовательно, `--jobs` игнорируется (при явной передаче — предупреждение);
- в окружение добавляются `GIT_REPOS_NAME` (имя каталога) и `GIT_REPOS_PATH` (абсолютный путь);
- ошибка команды не прерывает обход: печатается её код выхода, в конце — список упавших;
- Ctrl-C прерывает обход, а не переходит к следующему репозиторию; общий `--timeout` для `do` по
  умолчанию выключен (действует, только если передать флаг явно);
- `--remote` отбирает записи без локальной копии — выполнять там нечего, они пропускаются с
  предупреждением;
- `--dry-run` печатает `cd <путь> && <команда>` и ничего не запускает.

Провайдер и токен нужны только если задан хотя бы один фильтр из группы `diff`; `--feature`,
`--in-develop`, `--wip` и запуск без фильтров работают полностью локально.

Коды возврата: `0` — все команды успешны или выборка пуста, `2` — хотя бы одна упала.

### update

`git fetch origin <default-branch>` по всем сопоставленным репозиториям, параллельно (`--jobs`).
Пока идёт работа, в stderr крутится спиннер: сначала локальный скан и запрос списка, затем
`fetch · dimkarp93/git-repos · 40% (4 of 10) · in flight — 8`. Спиннер включается только когда stderr — терминал, и снимается
флагом `--no-progress`, поэтому в пайпах и логах вывод чистый.

### sync

- Локальный репозиторий без origin (или с origin на несуществующий репозиторий вашего аккаунта) → создаётся
  **приватный** репозиторий с именем каталога, прописывается `origin`, текущая ветка пушится; ссылки на созданные
  репозитории печатаются в конце.
- Локальный репозиторий, у которого origin уже указывает на **пустой** репозиторий вашего аккаунта (ни одной
  ветки на той стороне) → пушится текущая ветка. Так чинится случай, когда при прошлом `sync` коммитов ещё
  не было и push был пропущен. Проверка дешёвая: API спрашивается только у тех репозиториев, где нет ни одного
  `refs/remotes/origin/*`.
- Репозиторий, который есть только на GitHub → клонируется в каталог `--into` (флаг обязателен, каталог должен существовать; `~` раскрывается). Каталога по умолчанию нет.
- Конфликты пропускаются: имя уже занято на аккаунте, каталог назначения существует, владелец origin — не вы,
  remote указывает на другой хостинг. `--dry-run` показывает план, ничего не меняя.

### clean-local / clean-remote

По каждому репозиторию задаётся вопрос без варианта по умолчанию:

```
  [yes | yes-to-all | skip | skip-to-all]:
```

`yes` — удалить этот, дальше спрашивать; `yes-to-all` — этот и все последующие без вопросов; `skip` — пропустить
этот, дальше спрашивать; `skip-to-all` — выйти из команды. Флаг `--yes` равносилен `yes-to-all` с первого
репозитория, `--dry-run` печатает список кандидатов. `clean-local` предупреждает о незакоммиченных изменениях;
`clean-remote` требует у токена право `delete_repo`.

## Установка

```sh
just build      # ./git-repos в корне репозитория
just install    # ~/.local/bin/git-repos
```

### Автодополнение

`git-repos completion bash|zsh` печатает скрипт автодополнения: команды, флаги команды, значения
`--provider`, `--protocol`, `--timeout`, каталоги для `-C` и `--into`. Для `do` дополнение после
фильтров передаётся шеллу, поэтому дополняется обычная команда.

```sh
git-repos install-completions         # навсегда: файлы + строки в ~/.bashrc и ~/.zshrc
git-repos install-completions bash    # навсегда, только bash
git-repos uninstall-completions all
source scripts/enable-completion.sh   # только текущая сессия, на диск не пишет
```

Подробно — [docs/completion.ru.md](docs/completion.ru.md): ручная установка, что дописать
в `~/.bashrc` и `~/.zshrc`, чем сессионная установка отличается от постоянной, что делать, если
не работает.

## Использование

```sh
export GITHUB_TOKEN=ghp_...
git-repos                          # список команд (без команды ничего не выполняется)
git-repos -h                       # список команд и общие флаги
git-repos diff -C ~/tools --fetch
git-repos status -C ~/tools
git-repos update -C ~/tools
git-repos sync -C ~/tools --into ~/tools --dry-run
git-repos clean-local -C ~/tools
git-repos clean-remote --yes
git-repos status -C ~/tools --wip
git-repos diff -C ~/tools --behind --conflict
git-repos do -C ~/tools --in-develop -- git status -s
git-repos do -C ~/tools -- 'git log --oneline -1 | cat'
```

Коды возврата: `0` — расхождений нет, `1` — есть, `2` — ошибка запуска.

### Флаги

Общие для всех команд: `-C <dir>` (можно повторять), `--provider github`, `--depth N`, `--jobs N`,
`--timeout`, `--no-cache`, `--clear-cache`, `--no-color`, `--color`.

| Флаг | Команды | Назначение |
| --- | --- | --- |
| `--fetch` | diff | выполнить `git fetch origin <branch>` перед сравнением |
| `--all` | diff | показывать и синхронные репозитории |
| `--json` | diff | машинный вывод |
| `--refresh` | diff, update | игнорировать кэш дефолтных веток (файл при этом перезаписывается свежими данными) |
| `--no-cache` | все | не читать кэш и ничего в него не писать, файл на диске не трогать |
| `--clear-cache` | все | удалить файл кэша перед работой и наполнить его заново |
| `--no-progress` | diff, status, update, sync, do | не показывать спиннер |
| `--dry-run` | sync, clean-*, do | показать план, ничего не менять |
| фильтры | diff, status, do | см. раздел «Фильтры» |
| `--into <dir>` | sync | **обязательный**: каталог для клонирования |
| `--protocol ssh\|https` | sync | протокол для новых remote и клонов |
| `--yes` | clean-* | не спрашивать, считать ответ `yes-to-all` |
| `--version`, `--origin`, `--buildinfo` | — | сведения о сборке |

Коды возврата команд, кроме `diff`: `0` — успех, `2` — были ошибки.

### Окружение

`GITHUB_TOKEN` (или `GH_TOKEN`) — обязателен. `GITHUB_API_URL` и `GITHUB_HOST` переопределяют адрес API и хост
remote-адресов (GitHub Enterprise, тесты).

## Конфигурация

`~/.config/git-repos/config.yaml` (все поля необязательны):

```yaml
provider: github
cache_dir: ~/.local/git-repos
clone_protocol: ssh
roots:
  - ~/tools
  - ~/work
ignore:
  - node_modules
  - vendor
```

Дефолтные ветки кэшируются в `<cache_dir>/defaults.json` (TTL 7 дней). Кэш можно обойти (`--no-cache`)
или снести перед запуском (`--clear-cache`). Туда же под ключами `scan:<корень>`
пишется число каталогов, обойдённых в прошлый раз, — по нему считается процент локального скана.

### Как считается процент

Процент всегда внутри фазы, общего процента по команде нет; номер фазы печатается как `n/N`.
В строке спиннера номер и название фазы выделены **жирным**, процент и доля — зелёным, текущий объект
и счётчик `in flight` — серым (цвет снимается `--no-color` и переменной `NO_COLOR`).

- **локальный скан**: если для корня есть число каталогов от прошлого прогона — процент по нему
  (`26407 of 27471 directories`); если корень новый — по поддеревьям первого уровня, которые
  перечисляются одним `readdir` перед обходом (`3 of 17 subtrees`). Число каталогов сохраняется
  в кэш в конце обхода, так что со второго запуска процент плавный.
- **github api**: общее число репозиториев берётся из `GET /user` (`public_repos + total_private_repos`,
  этот запрос и так делается ради имени аккаунта); если счётчиков нет — из заголовка `Link` берётся
  `rel="last"`, и процент считается по страницам.
- **сопоставление**, **проверка веток**, **fetch**, **статус репозиториев**: обработанные репозитории
  к общему числу. В параллельных фазах `done` растёт только на завершённых, поэтому рядом печатается
  `in flight — N`.
